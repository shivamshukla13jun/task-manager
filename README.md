# E-commerce API — Node.js + TypeScript Starter

Production-ready Express + MongoDB + TypeScript starter with pluggable file storage (local / AWS S3 / Cloudinary / Firebase), MongoDB transaction-aware uploads with automatic rollback, hybrid RSA+AES payload encryption, and auto-generated Swagger docs.

## Features

- **Environment-driven config** — `.env.development` / `.env.staging` / `.env.production` selected by `NODE_ENV`. No hardcoded values; `src/config/env.ts` validates required vars at boot.
- **Pluggable storage** — one interface, five providers switched by `STORAGE_PROVIDER`:
  | Provider | Env value | Notes |
  |---|---|---|
  | Local disk | `local` | writes under `UPLOAD_BASE_DIR`, served at `/uploads/*` |
  | AWS S3 | `s3` | `@aws-sdk/client-s3`, optional custom `AWS_S3_ENDPOINT` (S3-compatible) |
  | Cloudinary | `cloudinary` | `resource_type: auto`, folder via `CLOUDINARY_FOLDER` |
  | Firebase Storage | `firebase` | uses `firebase-admin` + `FIREBASE_STORAGE_BUCKET` |
- **Upload middleware** — multer memory storage → provider upload → `File` document → file id written into `req.body[fieldName]`. Size + MIME whitelist from env.
- **Transactional file safety** — `withTransaction(handler)` runs the handler inside a MongoDB session (`req.dbSession`). On any error/abort: transaction rolls back **and** every file uploaded in the request is deleted from storage + the `files` collection. Replaced files can be queued for post-commit deletion via `req.deleteOnCommit`.
- **Hybrid payload encryption** — RSA-OAEP-SHA256 wrapped AES-256-GCM session keys. Tamper-proof (GCM auth tag), replay-protected (`ts` + `ENCRYPTION_MAX_AGE_MS`), per-request keys. Gated by `ENCRYPTION_ENABLED` + `isencrypted: true` request header.
- **Auto Swagger** — spec generated by walking the registered routers: zod validation schemas → request bodies, upload middleware → `multipart/form-data` with `binary` fields, `verifyToken` → `bearerAuth` security. Served at `/api-docs`.
- JWT auth (access + refresh, DB-tracked, TTL expiry), RBAC, Redis, RabbitMQ, BullMQ, Winston logging, Zod validation, Helmet, rate limiting.

## Quick start

```bash
npm i

# infra (redis + rabbitmq) — mongo runs separately (replica set needed for transactions)
docker compose up -d

# dev — loads .env.development
npm run dev
```

Env files are loaded by `NODE_ENV`: `dev` script → `.env.development`, `start:staging` → `.env.staging`, `start` / `start:pm2` → `.env.production`. Copy `.env.example` and fill in per environment.

> **Transactions need a MongoDB replica set.** Standalone `mongod` can't run sessions/transactions — either run a single-node replica set (`--replSet rs0` + `rs.initiate()`) or add `?replicaSet=rs0` to `MONGO_URI`.

## File uploads + transactions

```ts
import { upload, withTransaction } from 'middlewares';

router.post(
  '/',
  upload.single('avatar', { folder: 'users', types: ['image'] }),  // → req.body.avatar = File id
  validateUserRegistration,
  withTransaction(createUser)                                       // mongo session + rollback
);
```

Inside a `withTransaction` handler, pass `req.dbSession` to queries:

```ts
await User.create([req.body], { session: req.dbSession });
await user.save({ session: req.dbSession });
await User.findById(id).session(req.dbSession);
```

Rollback behavior:

- error thrown / `next(err)` / connection aborted → `abortTransaction()` + all `req.uploadedFiles` deleted from provider storage **and** the `files` collection
- the global error handler runs the same cleanup for failures outside a transaction (e.g. zod validation)
- `deleteFileOnCommit(req, { key, provider, fileId })` marks an old file for deletion **after** commit (used for replaced avatars)

Upload options: `upload.single(field, { folder, types })`, `upload.array(field, max, opts)`, `upload.fields([{name, maxCount}], opts)`. `types` restricts to `image | video | document | audio` groups; otherwise `ALLOWED_FILE_TYPES` / `UPLOAD_MAX_SIZE` env applies.

## Payload encryption (RSA + AES-GCM)

Enable with `ENCRYPTION_ENABLED=true`. The client:

1. `GET /encryption/public-key` → server RSA public key (PEM)
2. generates a random AES-256-GCM key, encrypts payload `{...data, ts: Date.now()}`, wraps the AES key with the RSA key
3. sends `isencrypted: true` + `x-ek: <wrapped key>` headers; body `{ iv, data }` — for multipart, `iv`/`data` become form fields and files go raw

Server decrypts `req.body`, and `res.json` responses go back as `{ iv, data }` under the same session key.

- **Confidentiality**: only the server's private key can unwrap `ek` — a middleman sees ciphertext
- **Integrity**: GCM auth tag — any modified byte fails decryption (`400`)
- **Replay**: `ts` must be within `ENCRYPTION_MAX_AGE_MS` (default 5 min)
- Disabled (`ENCRYPTION_ENABLED=false`) or missing header → requests pass through untouched

Keypair paths: `ENCRYPTION_PRIVATE_KEY_PATH` / `ENCRYPTION_PUBLIC_KEY_PATH` (default `keys/`). Auto-generated on first boot if absent. `keys/` and `*.pem` are gitignored — never commit the private key.

### React client

`examples/secure-frontend/` is a working Vite + React + TS demo. The reusable client is `src/lib/SecureApiClient.ts` — drop it into any app:

```ts
const api = await new SecureApiClient(baseUrl).init();
const r = await api.post('/api/auth/login', { email, password });
// r.body — decrypted response; r.wire — what crossed the network
```

Run it:

```bash
cd examples/secure-frontend && npm i && npm run dev   # http://localhost:5173 (vite proxy → :3000)
# or: npm run build → served same-origin at http://localhost:3000/secure-demo
```
